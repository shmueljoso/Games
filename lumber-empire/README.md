# אימפריית העצים — ארכיטקטורה

משחק אידל/הפרשה: חוטבים עצים ביד, בונים שרשרת ייצור שלמה (עצים ← קורות
← עיסת נייר ← נייר ← מכירה), וכשהאימפריה גדולה מספיק — "פותחים יער חדש"
(פריסטייג') תמורת זרעי זהב שמעלים תפוקה לתמיד.

```
lumber-empire/
├── index.html            ← ה-DOM, ה-CSS, לולאת הרינדור והקלט
├── engine.js             ← מנוע המשחק הטהור — בלי DOM, ניתן ל-require מ-Node
├── test-balance.js       ← בדיקות יחידה + סימולציית בוט לאיזון (node test-balance.js)
├── manifest.webmanifest  ← הגדרות התקנה כאפליקציה
├── sw.js                 ← service worker לריצה גם בלי רשת
└── icon-*.png            ← אייקונים למסך הבית
```

## שרשרת הייצור

חמישה סוגי בניינים, כל אחד ממיר את תפוקת הקודם למשאב הבא:

```
חוטב עצים ──▶ עצים ──▶ מסור ──▶ קורות ──▶ טחנת עיסה ──▶ עיסה ──▶ מכבש נייר ──▶ נייר ──▶ צוות מכירות ──▶ כסף
```

כל בניין: כמות בלבד (בלי "רמות" נפרדות), מחיר קנייה שעולה גיאומטרית
(`baseCost * growth^count`), ותפוקה = `count * rate * globalMult`. כל
שלב (מלבד הראשון) צורך יחס קבוע מהמשאב שלפניו (`ratio`, כרגע 2:1 בכל
שלב) — כך שתמיד יש למה לחכות: יותר עצים דורש יותר מסורים כדי לא
להצטבר סתם, וכן הלאה במורד השרשרת.

### הבאג המרכזי שנתפס בסימולציה: אין כסף בלי כסף

בגרסה הראשונה של המנוע, כל הבניינים עלו כסף — אבל שום דבר לא הפך למשאב
"כסף" חוץ מהשלב האחרון בשרשרת (`salesTeam`). זו לולאה בלתי אפשרית:
כדי לקנות אפילו את הבניין הראשון צריך כסף, וכדי להרוויח כסף צריך לבנות
את **כל** חמשת השלבים קודם. סימולציית הבוט ב-`test-balance.js` תפסה
את זה מיד — אחרי 4 שעות סימולציה שום בניין לא נקנה בכלל.

הפתרון: `applyMarketTrickle` — לכל משאב ביניים (עצים/קורות/עיסה/נייר)
יש מחיר בסיס בשוק הפתוח, ואחוז קטן מהמלאי (6% לשנייה) נמכר "ממילא"
בכל טיק, במחיר נמוך משמעותית ממה שבניין ייעודי היה נותן. זה מה שמאפשר
להתחיל מאפס: חוטבים עץ ביד → העץ מצטבר וגם מטפטף כסף → קונים חוטב עצים
→ יותר עצים מצטברים ומטפטפים → קונים מסור, וכן הלאה. בניית השלב הבא
תמיד משתלמת יותר מהטפטוף, כי הוא ממיר בכמויות גדולות מיד במקום לאט
ובאחוזים.

## פריסטייג'

`state.moneyThisRun` נספר מאפס בכל פעם (בניגוד ל-`lifetimeMoney`
שלא מתאפס לעולם, ומוצג רק לצורכי סטטיסטיקה). כמות הזרעים שפריסטייג'
היה נותן **עכשיו**: `floor(SEEDS_K * sqrt(moneyThisRun - SEEDS_MIN_MONEY))`
(0 אם עוד לא הגעתם לסף). ה-`SEEDS_MIN_MONEY` קיים כדי שהפריסטייג'
הראשון לא יהיה זמין אחרי כמה שניות בגלל השיפוע התלול של שורש ליד
האפס — זו אמורה להיות החלטה משמעותית, לא רפלקס.

בפריסטייג' בפועל: `prestige.seeds` מצטבר (לא מתאפס), כל שאר המצב
(משאבים, בניינים, רמת הגרזן, `moneyThisRun`) מתאפס. `globalMult` (מכפיל
שחל על כל תפוקה, כולל כוח הלחיצה הידנית) הוא `1 + seeds * 0.02`.

## התקדמות אופליין

`fastForward(state, seconds)` מריץ את אותה לוגיקת `tick` בכמה עשרות
צעדים קטנים (לא צעד ענק אחד), כדי לשמור על דיוק סביר של צווארי-הבקבוק
בשרשרת גם על פני שעות של זמן שחלף. ב-`index.html`, בטעינה מושווה
`lastSaveTime` השמור מול הזמן הנוכחי (מוגבל ל-8 שעות), והתוצאה מוצגת
כמסך "ברוכים השבים" עם סיכום הרווח.

## בדיקות איזון

`test-balance.js` מריץ 11 בדיקות יחידה ואז בוט חמדן ("קנו תמיד את
הזול ביותר שאפשר להרשות") על 4 שעות זמן-משחק, ומוודא: אף משאב לא הופך
שלילי/NaN, כל סוגי הבניינים בפועל נקנים (אין צוואר בקבוק), ופריסטייג'
ראשון בר-השגה תוך פחות משעה. להרצה: `node test-balance.js`

## נייד, PWA ושמירה

שמירה אוטומטית ב-`localStorage` כל שנייה ובכל `visibilitychange`/
`beforeunload`. אין CDN חיצוני מלבד גופני Google Fonts (עם fallback
מלא). ה-service worker שומר את כל המשחק במטמון אחרי ביקור ראשון.

פריסה: `wrangler pages deploy .` או כל שרת סטטי — אין שלב בנייה.
