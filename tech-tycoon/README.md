# מסלול הברזל — ארכיטקטורה

סימולציית קריירה בתעשיית הטכנולוגיה. קובץ HTML סטטי אחד, ללא build ,ללא תלויות
חיצוניות וללא CDN — מוכן להעלאה ל-Cloudflare Pages כמו שהוא.

```
tech-tycoon/
├── index.html            ← הכל: CSS, מנוע, ממשק
├── manifest.webmanifest  ← הגדרות ההתקנה כאפליקציה
├── sw.js                 ← service worker: ריצה גם בלי רשת
└── icon-*.png            ← אייקונים למסך הבית
```

## נייד והתקנה כאפליקציה

הממשק נבנה לשני עולמות. במסך רחב: סרגל ניווט צדי, טבלאות מלאות ורשת של עד
ארבעה טורים. במסך צר: שבבי ניווט נגללים ודביקים בראש, כפתור התור מקובע
בתחתית בטווח האגודל, טבלאות המוצרים הופכות לכרטיסים, ועמודות משניות נעלמות.
המודאלים הופכים לגיליון תחתון עם כותרת ותחתית מקובעות וגוף שנגלל, כך
שכפתורי הפעולה תמיד נגישים.

**כל מודאל ניתן לסגירה** — בלחיצה על הרקע, בכפתור X או ב-Escape. גם חלון
אירוע שמבקש החלטה ניתן לדחייה, ורינדור שנכשל נתפס ומוצג כחלון שגיאה שאפשר
לסגור. בטלפון אין מקש Escape, ולכן אסור שיהיה מסך שנועל את המשחק.

להתקנה: פותחים את המשחק מכתובת אינטרנט (Cloudflare Pages, GitHub Pages או
כל שרת סטטי) ובוחרים "התקנה כאפליקציה". באנדרואיד הדפדפן יציע התקנה; באייפון
זה **שיתוף → הוספה למסך הבית**. אחרי ההתקנה המשחק רץ במסך מלא ועובד גם
בלי רשת, וההתקדמות נשמרת במכשיר.

פריסה: `wrangler pages deploy .` או גרירת התיקייה ל-Cloudflare Pages.
אין שלב בנייה, אין `node_modules`, אין קריאות רשת בזמן ריצה (מלבד Google Fonts,
שיש לו fallback מלא).

## העיקרון שמנחה את המנוע

**אין תאריכים קשיחים.** אין שורת קוד שאומרת "ב-2030 עוברים למשקפיים".
לכל קטגוריית מוצר (פרדיגמה) יש `viab` — סף היתכנות מסחרית. מולו מחושב
`ready` — הידע הטוב ביותר שקיים בעולם בצמתים שמאפשרים אותה:

```js
ready(p) = Σ  frontier(k) · weight(p,k)      // לכל צומת k שמאפשר את p
frontier(k) = max over all companies of tech[company][k]
```

`frontier` הוא מקסימום על **כל** החברות, כולל השחקן. מכאן נובע:

| מצב | תוצאה |
|---|---|
| אף חברה לא מממנת את הצמתים | הקטגוריה לא נפתחת לעולם |
| השחקן מוביל ופותח | הוא ראשון בשוק — ומרים את הגבול גם ליריבים |
| יריב פותח ראשון | ההוצאה העולמית זזה לשם בלי השחקן |

הביקוש מתחלק בין הקטגוריות לפי אטרקטיביות, שנגזרת מהבשלות, מאיכות המוצר
הטוב ביותר שקיים בקטגוריה ומחיכוך אימוץ (`PULL`) — לא מלוח שנה:

```js
mat(p)   = (ready(p) − viab(p)) / (100 − viab(p))
A(p)     = mat(p)^1.3 · (1 + bestScore(p)/80) · PULL(p) · (1 + heat(p))
spend(p) = marketTotal · A(p) / ΣA
```

וכשנפתחת קטגוריה חדשה **העוגה גדלה** ולא רק מתחלקת מחדש
(`marketTotal` גדל עם רוחב הקטגוריות הבשלות).

## State Management

מצב יחיד, שטוח וסריאליזבילי במלואו — `JSON.stringify(S)` מספיק לשמירה,
ואין הפניות מעגליות, פונקציות או תאריכים בתוך המצב.

```js
G = {
  rs, seed,                  // מחולל אקראיות דטרמיניסטי — אותו זרע = אותו עולם
  t,                         // מספר החודש (0 = ינואר 2025)
  me,                        // מזהה החברה שהשחקן מנהל כרגע
  cos: {                     // כל החברות — כולל השחקן, באותו מבנה בדיוק
    [id]: {
      cash, debt, brand, board, baseRev, expect,
      tech: {node: 0..100},  // 22 צמתי ידע
      alloc: {node: weight}, // הקצאת מו״פ (השחקן ידנית, AI אוטומטית)
      rndBudget, marketing,
      staff: [person],       // אנשי מפתח שגויסו
      products: [product],
      contracts: [contract],
      style: {agg, ops, rndShare, focus},   // ה"אישיות" שמניעה את ה-AI
      hist: [{t,rev,op,net,share,...}],
      isMe, distress, counter
    }
  },
  para: {[p]: {ready, mat, open, share, spend, momentum, heat}},  // נגזר, מחושב מחדש כל חודש
  market: {total, base, growth, breadth0},
  spot: {component: priceIndex},   // שוק הספוט
  suppliers: [...],
  talent: [candidate],       // מאגר מועמדים חי
  startups: [target],        // מטרות רכישה
  macro: {tax, tariff, sentiment, shock, shockLeft, rate},
  ops: {esp, sab, hype, cin, target},        // תקציב שחור
  career: {rep, tenure, firedCount, titles[], history[], offers[]},
  news[], log[], hist[], opsLog[], flags{}
}
```

**נקודת המפתח בארכיטקטורה:** גם השחקן וגם היריבים הם רשומות זהות ב-`cos`,
ורצים דרך אותן פונקציות (`rndTick`, `financeTick`, `marketTick`). ההבדל היחיד
הוא ש-`aiTick` מדלג על החברה שמסומנת `isMe`. מכאן שהחלפת כיסא באמצע המשחק —
פיטורים, מעבר לחברה אחרת, נפילה לסטארטאפ — היא שינוי של שדה אחד:

```js
from.isMe = false;  to.isMe = true;  G.me = to.id;
```

בלי קוד מיוחד, בלי מסלול נפרד, ובלי לאבד את העולם.

## סדר הפעולות בתור חודשי

```
macroTick      → זעזועים, סנטימנט, ריבית
supplyTick     → מחירי ספוט, מימוש חוזים, take-or-pay
rndTick   ×N   → כל החברות מקדמות ידע
aiTick    ×N   → כל היריבות מחליטות (מיקוד, השקה, מחיר, רכישה)

launch loop    → מוצרים שהגיע מועדם עולים לשוק (עם סיכון תקלה)
```

## הרחבה

* **קטגוריה חדשה** — הוסיפו רשומה ל-`PARA` עם `en` (צמתים מאפשרים), `viab`,
  `recipe` ו-`dev`. השאר (שוק, AI, מוצרים, ממשק) מתחבר לבד.
* **צומת ידע חדש** — הוסיפו ל-`TECH` ול-`FRONT0`.
* **חברה חדשה** — הוסיפו ל-`CO_DEFS`; `playable:1` יוסיף אותה למסך הבחירה.
* **אירוע חדש** — הוסיפו ל-`EVENTS` עם `o[]` של אפשרויות; כל `fn(G)` מחזירה
  מחרוזת תיאור ומשנה את המצב ישירות.
* **מודול חדש במכשיר** — הוסיפו ל-`PARTS` עם `node` (צומת הידע שהוא חושף),
  `comp` (הרכיב בשרשרת האספקה) ו-`w` (משקלו בציון). המגדיר, ה-BOM והניקוד
  מתעדכנים לבד.
* **יתרון מבני חדש** — הוסיפו מפתח ל-`traits` של חברה, טקסט ל-`TRAIT_TXT`,
  והתייחסות אליו ב-`appealOf` / `bomOf` / `financeTick`.

## שני מסלולי פתיחה

המשחק מתחיל ביצירת דמות — שם, כינוי ערוץ, אווטאר — ואז בבחירת מסלול.

**כיסא המנכ״ל**: אחת מעשר חברות, מיליארדים בתקציב ודירקטוריון שסופר רבעונים.

**יוצר תוכן**: ערוץ ריק, 20 אלף עוקבים ו-8 מיליון דולר. כל חודש מעלים סרטון אחד:
ביקורת מכשיר, תחקיר על חברה, סרטון ממומן, תוכן עומק, או שדרוג הסטודיו. הציון
שאתם נותנים מזיז את ממוצע הביקורות של המכשיר ואת המכירות שלו בפועל, במשקל
`עוקבים × אמינות`. ככל שתהיו קרובים לאיכות האמיתית — האמינות עולה וההשפעה
גדלה; מי שמוכר ציונים מגלה שהכסף נשאר אבל הקול נעלם.

בעולם פועלים שמונה יוצרים נוספים, לכל אחד קהל, אמינות, נטייה והתמחות.
**ציון הביקורות של כל מכשיר בהשקה הוא הממוצע המשוקלל של דעות כל הקהילה** —
לא נוסחה סגורה. תקציב ההייפ של חברה קונה יוצרים ספציפיים, וזה נראה לקהל.

עם 1.2 מיליון עוקבים ואמינות 40 אפשר להפוך את הקהל לחברה: הגיוס נגזר מגודל
הקהל, המותג מתחיל גבוה, מכשיר ראשון נכנס לפיתוח — ומכאן זה המשחק המלא.
בבדיקת איזון על פני ארבע שנים: מבקר ישר הגיע ל-10.5 מיליון עוקבים ואמינות 99,
מי שחי מחסויות הגיע ל-4.4 מיליון עם אמינות 5 (כלומר בלי השפעה), ותחקירן
הגיע ל-3 מיליון עם אמינות 84.

## יחסי חברות ויוצרים

לכל יוצר יש **זווית** — מה הוא בודק קודם: ביצועים, צילום, עיצוב, סוללה, אודיו,
אוטונומיה, חדשנות או תמורה למחיר. הזווית נבדקת מול **המודולים שבחרתם במגדיר
המכשיר**, ולכן מצלמה בדרגה 5 מרימה את הציון של מבקרת צילום ולא מזיזה למי
שמודד ביצועים. בבדיקה: אותו מכשיר בדיוק, מצלמה בדרגה 1 מול דרגה 5 — מבקרת
הצילום נתנה 3.8 מול 6.0, וכל השאר נתנו בדיוק אותו ציון.

חברה יכולה לפנות ליוצר בשלוש דרכים:

| פעולה | עלות | מה היא קונה |
|---|---|---|
| שליחת יחידת ביקורת | $4M | **כיסוי** — היוצר יסקר את מה שתשיקו בחצי השנה הקרובה, גם אם זו לא הקטגוריה שלו. לא קונה ציון: מכשיר גרוע יקבל קטילה, והיחסים ייפגעו. |
| הזמנה לאירוע חשיפה | $2M | **יחסים** שנצברים לאורך שנים ומרימים קלות את הציון. |
| חסות | לפי גודל הקהל | **ציון** (+1.3) — במחיר אמינות היוצר, וזו בדיוק האמינות שנותנת משקל לדעה שקניתם. |

**כיסוי הוא משאב.** מי שמסקר מכשיר בהשקה הם היוצרים הגדולים, אלה שהקטגוריה
שלהם, ומי שקיבל יחידה. כיסוי דל אומר פחות קולות בממוצע — ותוצאה תנודתית
בהרבה. בבדיקה: שליחת שלוש יחידות העלתה את הכיסוי מארבעה יוצרים לשבעה.

בצד השני של המשוואה, השחקן־היוצר מקבל יחידות ביקורת מחברות: חשיפה מוקדמת
שווה 30% יותר צפיות, בלי התחייבות לציון — אבל מי שמקטל יזכה לפחות חבילות.

## מערכות שנוספו בגרסה השנייה

### מגדיר המכשיר
**המודולים משתנים לפי סוג המוצר.** לסמארטפון יש מעבד, צילום, מסך, סוללה, זיכרון,
חומרים ומודם. לבינה סביבתית אין מסך בכלל — יש מערך מיקרופונים, מודם והזנה
אלחוטית. לרובוט יש מפעילים, מחשב אוטונומיה, חישה מרחבית ושלדה. למשקפיים יש
מדריכי גל אופטיים. כל מודול קשור לצומת ידע אחר ולרכיב אחר בשרשרת האספקה,
ולכן **המתכון של שרשרת האספקה נגזר מהמודולים** ולא מרשימה נפרדת (`recipeOf`).

כל מודול בחמש דרגות. הדרגה עושה שני דברים בו-זמנית: קובעת כמה מהידע שלכם באותו צומת מתבטא
במוצר בפועל, ומכפילה את עלות הרכיב המתאים בשרשרת האספקה
(`TIER_Q` מול `TIER_COST`). דרגה נמוכה בתחום שאתם מובילים בו היא ידע מבוזבז,
והממשק אומר זאת במפורש.

```js
score = base(paradigm) × (0.62 + 0.38·cfgQuality) + Σ w·(tech[node]−58)·0.115·TIER_Q
BOM   = Σ recipe[comp] × spot[comp] × TIER_COST[tier]
```

### כנס חשיפה וביקורות
לפני ההשקה בוחרים רמת אירוע (ללא / חשיפה סטנדרטית / כנס ראווה) שעולה כסף
ומזניק הייפ. בהשקה נקבע ציון ביקורות 1–10 יחסית **לטוב ביותר שקיים באותו רגע
בקטגוריה** ולתמורה למחיר. הציון מכפיל את האטרקטיביות בארבעת החודשים הראשונים
ואז מתפוגג. הייפ גבוה מול ביקורות חלשות גורר קנס — הציפיות נענשות.

### אקוסיסטם ונעילת משתמשים
כל מכשיר שנמכר נכנס ל`installed` (שנשחק ב-1.6% לחודש). `lockin` נגזר
מטכנולוגיית הפלטפורמה, מרוחב הקטגוריות הפעילות ומנתח השוק, ומייצר הכנסה
חוזרת: `services = installed × arpu`. נעילה גבוהה מוסיפה עד 17% לאטרקטיביות
של כל מוצר — ובה בעת הופכת למלכודת כשהעולם עובר קטגוריה, כי הבסיס המותקן
תקוע בקטגוריה הישנה.

### יתרונות מבניים
| חברה | יתרון | מימוש |
|---|---|---|
| Chroma | ריבוי מותגים | שני דורות חיים במקביל באותה קטגוריה בלי קניבליזציה מלאה |
| Sahara | הפצה לא מקוונת + הנדסה לעלות | בונוס אטרקטיביות שגדל ככל שהמחיר נמוך, ו-13% פחות עלות ייצור |
| CineMatix | אספקת רכיבים | תמלוגים על כל יחידה שנמכרת בתעשייה, שגדלים עם ההובלה באופטיקה |
| Echo | קשרי ספקיות סלולר | בונוס נוכחות במדף במחיר סבסוד שיורד מהשוליים |

### שמירה וטעינה
ארבעה חריצים ב-`localStorage` (חריץ 0 נשמר אוטומטית בכל תור), plus ייצוא
וייבוא של המצב המלא כטקסט להעברה בין מכשירים.
